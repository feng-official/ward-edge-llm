# 标签规范 v1.0.0

## 主字段

每条记录包含：

- `id`：稳定样本编号，格式 `nlu-NNNN`。
- `event_type`：必须属于项目事件字典定义的 13 类事件。
- `description`：提供给 LLM 的自然语言事件描述。
- `context`：病区、床位、置信度、时间、网络、规则命中和结构化观测。
- `labels`：期望模型输出的风险等级、紧急程度、护理建议和处置判断。
- `source`：`manual/real_event/diffusion`。当前版本全部为人工设计模板生成，标为 `manual`。
- `split`：`train/test`；`test` 不得参与训练、蒸馏、阈值选择或提示词调优。

## 风险等级与紧急程度

| 风险 | 紧急程度 | 事件类型 |
|---|---|---|
| P1 | 紧急 | 疑似跌倒、抽搐检测、坠床预警、护士呼叫 |
| P2 | 警告 | 离床、异常体态、长时间静止、夜间徘徊、门区异常离开 |
| P3 | 提醒 | 压疮风险、环境异常、设备故障、节点失联 |

事件被判为 `reject` 时仍保留原事件风险等级，因为风险等级表示事件类型的默认响应级别，
`judgment` 才表示本次证据是否支持告警。

## 处置判断

- `confirm`：连续观测或两个以上信息源支持事件，且没有合理的正常活动解释。
- `reject`：存在明确相反证据，或能由维护、护理、康复训练、传感器抖动等正常情况解释。
- `escalate`：证据缺失、遮挡、信息源冲突或处于阈值边缘；不能安全确认，也不能排除。

置信度只是判断依据之一。数据中特意保留了高置信误报和低置信真实事件，避免模型退化为
只按置信度阈值分类。

## 护理建议

护理建议应当：

1. 给出可执行的床旁复核或安全措施，通常不超过 3 个动作。
2. 只提供护理辅助提示，不作疾病诊断，不替代医护人员判断。
3. `confirm` 强调立即或按风险等级处置；`reject` 强调人工确认和设备校准；
   `escalate` 强调补充证据、持续观察以及必要时升级。
4. 涉及跌倒、抽搐、意识异常时，不建议未经评估随意搬动患者。

## 划分规则

- 每个事件类型按 80%/20% 分层进入训练集和测试集。
- 测试集使用每个 `event_type + judgment` 的保留场景族。
- 训练/测试的 ID、完整描述和 `scenario_family` 均不得交叉。
- 同一条主样本派生出的两种 Qwen 任务必须留在同一 split，避免视图级泄漏。

## 人工审核要求

真实事件或误报回流只能在脱敏并经人工审核后加入新版本。涉及患者身份、原始视频、
病历和用药等信息不得直接进入本数据集。任何标签调整都必须升级版本并记录变更。
