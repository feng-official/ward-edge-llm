# 病房 NLU 任务数据集构建说明（P5 先伟）

> 依据《任务书》T6「数据与对比实验」，截止 **8/25**。有疑问随时对齐。

## 1. 任务目标

构建**不少于 500 条**病房 NLU（自然语言理解）评测数据，用于评测边缘/云端 LLM 对病房事件的理解与处置能力，并支撑**三种路线对比实验**（纯边缘 / 云边协同 / 纯云端）。

## 2. 每条样本包含 5 个标签字段

| 字段 | 含义 | 取值示例 |
|---|---|---|
| 事件描述 | 喂给 LLM 的自然语言输入 | "3床患者从床上滑落，检测到快速下坠动作" |
| 风险等级 | 事件优先级 | P1 / P2 / P3 |
| 紧急程度 | 紧急判断 | 紧急 / 警告 / 提醒 |
| 护理建议 | 期望 LLM 输出的处置建议 | "立即前往查看，评估意识，通知医生" |
| 处置判断 | 云端二次研判结果 | confirm / reject / escalate |

## 3. 数据格式（JSON，一行一条）

```json
{
  "id": "nlu-0001",
  "event_type": "fall_suspected",
  "description": "3床患者从床边滑落，检测到快速下坠动作，持续1.2秒",
  "context": {"ward": "W-01", "bed": "B03", "confidence": 0.85},
  "labels": {
    "priority": "P1",
    "urgency": "紧急",
    "advice": "立即前往病房查看，评估意识状态，检查外伤，通知主管医生",
    "judgment": "confirm"
  },
  "source": "manual"
}
```

- `event_type`：按项目 13 类事件填写（fall_suspected / bed_leave / seizure / nurse_call / night_wandering / abnormal_posture / long_still / bedsore_risk / door_departure / fall_prediction / environment_anomaly / device_fault / node_offline），枚举见 `docs/00-事件字典.md`
- `source`：`manual`（人工构造）/ `real_event`（真实事件回流）/ `diffusion`（扩散生成），用于后续"误报回流训练"闭环叙事

## 4. 数量与分布建议

- 总数 ≥ 500 条，建议 **400 训练 + 100 测试**（测试集独立，绝不参与训练/蒸馏）
- 按事件类型分层：重点事件（fall_suspected、seizure、fall_prediction）每类 40-50 条，其余每类 20-30 条
- 同一描述可做变体扩充：换床号、换时间、换置信度、加干扰信息，注意保持语义一致

## 5. 必须交付的东西

1. **数据集文件**（JSON + 版本号，如 `nlu-dataset-v1.0.0.json`）
2. **标签规范说明**（字段定义、取值枚举、标注准则——什么叫"跌倒"、什么叫"误报"）
3. **版本记录**（改样本必须升版本，记录变更内容）
4. **可重复的评测脚本**（能一键跑出指标，带原始日志）

## 6. 评测指标要求（配合三路线对比）

- 指标：**准确率、召回率、F1**（按事件类型分别报告，不能只看总体）+ 延迟 + 内存(RSS) + 断网保持率
- 所有指标要有明确分母、样本量、统计方法，**留存原始日志**，不得只给单次最好结果
- 断网业务保持率目标 **≥90%**，未达标需给出失败分类和整改方案
- 输出：三种路线对比表 + 图表 + 最终测评报告（含测试环境和限制说明）
